## 1. 总体方向：从角色小游戏升级为可复现的策略挑战作品

此前评价“个人小游戏约 8/10”可以保留，理由是轮廓碰撞、素材管线、输入体验和回归测试已有基础。评分是主观判断，不能替代用户数据。

最适合你的升级定位是：**保留轻松的角色合成和自研碰撞特色，增加每日同序列挑战、个人进步记录和可回放成绩。**

产品分三个阶段：
1. **学习与作品集版本**：保留纯静态部署，先补玩法入口、健壮性、模块边界及测试。
2. **朋友挑战版本**：加入固定序列、分享挑战码、本地回放；成绩可以明确标成未验证。
3. **公开排名版本**：独立后端、重放校验、服务端限流和运维预算齐备后，再开放可信榜单。

先集中完成这条主线。多人实时对战、账号商城、广告和复杂任务体系，会同时放大物理同步、数据与运营成本，暂缓。

## 3. P0：先完成可理解、可恢复、可独立运行的基础版本

### 3.1 常驻“玩法 / 图鉴”入口（预计3–5小时）

位置：index.html 的 actions、style.css 的窄屏规则、game.js 的输入和预览绘制。

- 桌面和手机都保留入口；打开后展示11级图像、等级编号、角色名称和升级箭头。
- 首次进入给三条提示：拖动后松手投放、同级碰撞合成、同一只停在警戒线上方累计1.5秒判负。
- 明确当前与下一只的标签，避免仅凭位置区分。图鉴采用文字与图片组成的 DOM 列表，便于阅读和访问。
- 说明2000分发币、顶级合成加500分并送币、复活只在本局有效。
- 打开说明时暂停世界和投放，关闭后恢复。弹窗支持 Escape、焦点进入/约束/返回；鼠标点击按钮不能同时投放。

验收：320×568、390×844、844×390、1440×900视口下入口可见、说明可滚动、关闭可达、棋盘不横向溢出。找5名没玩过的人，记录第一次投放和第一次合成的用时及误解，至少4人可在30秒内完成首次投放；这是目标，尚无实测用户数据。

### 3.2 暂停、存储和输入保护（预计4–7小时）

新增 pauseReason 或暂停原因集合，统一处理手动暂停、图鉴、排行榜、赞助弹窗、页面隐藏和系统中断，避免关闭一个弹窗就意外解除另一个暂停原因。

- 页面隐藏停止模拟推进；回来重置 last/acc，不补算离开时长。
- 当前帧循环已经是1/60秒固定步长并有追赶上限，保留这项基础。
- 使用模拟 tick 记录出生/落地相关时间；动画时间可独立。
- safeStorage 包装读写；最高分只接受有限、非负且合理的数字。存储不可用时继续玩，并提示设置仅本次有效。
- 多指触摸仅跟踪一个 pointerId；pointercancel 清理状态；按钮、输入框和弹窗中的按键不透传给游戏。
- 进行中的重开需要明确操作，避免一次误按损失长局；设置可选的震动和减弱闪光/动画。

验收：隐藏30秒后恢复无突进、不直接判负；模拟 localStorage 抛错和坏值后仍可启动；图鉴中按空格不会掉落；第二根手指不会提前释放第一根的投放。

### 3.3 副本身份与配置分离（预计2–4小时）

保留作者来源与 Fork 关系，新增自己的维护说明。将运行配置集中到 config：应用名、模式、榜单地址、提交开关、赞助开关。

独立开发默认使用本地榜单/关闭远程写入，避免把测试局提交到原榜。原二维码应标明赞助的是原作者，或在你的版本关闭该入口；不能只改“作者”文字导致归属混淆。当前 Fork 尚保持原样，未启用 Pages。

验收：自己的实例从网络记录可确认未调用原榜写入接口；昵称/最高分使用版本化键；README 明确源码副本链接和实际游玩链接。

## 4. P1：重建排行榜的数据正确性与信任边界

### 4.1 两档实现，按真实需求选择

**A档，学习/朋友版（预计4–7小时）**  
本地保存前20个个人记录或读取只读朋友榜；明确“未验证成绩”。恢复可读 leaderboard 源码和公开配置，保留 textContent 渲染、网络失败不阻塞游戏。该档不需要云端费用，也不能宣称防作弊。

**B档，公开挑战版（预计12–20小时，另需回放引擎）**  
静态前端 + 单一服务端 API + 数据库。服务端管理存储权限、runId、规则版本、挑战日期、提交状态和接受时间，客户端无数据库写入密钥。

建议接口契约：

| 接口 | 请求/响应要点 |
|---|---|
| GET /api/challenges/today | 返回challengeId、上海日期、seed或显式序列、rulesVersion、sequenceVersion |
| POST /api/runs | 领取有过期时间的runId与提交令牌；绑定挑战和规则版本 |
| POST /api/runs/{runId}/result | 提交昵称及输入日志；幂等，以同一runId复用同一结果 |
| GET /api/leaderboard?challengeId=… | 只读取已接受且模式一致的成绩，返回recordId、本人标记及更新时间 |

数据库关键约束：每个runId最多一条正式成绩；每日挑战只取玩家当天最佳有效局；最近成绩流和高手榜分开命名；同分规则固定并公开。时间用服务端接受时间，不信任客户端记录的排序时间。

- 服务端校验有限整数、昵称、日志长度、投放坐标、有效 tick、冷却、复活数量、比赛终止条件。
- 限制开始局、提交、读榜的请求频率和重放计算成本。匿名设备标识可减少误重复，不能保证“一人一个账号”；账号同样不能证明手动游玩。
- 同一局第一次提交成功但响应丢失，重试必须返回相同recordId；昵称改变不得创建新成绩。
- 改为按 runId 标记本人；避免打开弹窗或旧局请求完成后覆盖新局结算界面，绑定请求代次/局ID。
- 限定服务端CORS、请求大小、超时；这些保护不能代替校验成绩。
- 管理员异常成绩隔离、撤销和审查使用独立权限；不要自动误删玩家记录。

**信任层次必须写清**：校验数值范围只能挡格式错误；服务端签名能保护服务端产生的数据；服务端重放能证明一局输入符合规则。重放仍无法区分真人与脚本，若未来有奖项还需要额外机制。混淆前端、删调试入口、客户端签名均不能单独证明成绩真实。

验收：同一runId重复提交不重复计分；跨模式/旧版本成绩不混榜；非法日志被拒绝；高分仅在服务端算出后入榜；断网继续游戏且可明确重试。所有测试写入隔离测试数据库。

## 5. P1：每日同序列挑战与可回放成绩

### 5.1 先做本地可复现引擎，再接公开榜（预计8–14小时）

当前固定时间步是好的起点，进阶需要同时解决以下事项：

1. **随机源分离**：掉落使用固定版本的PRNG；粒子、音效和加载重试使用独立随机源。否则多画一帧粒子会改变下一只角色。
2. **时间分离**：landed、冷却、越线、复活、命中定格使用模拟tick。performance.now仅用于表现与帧调度。
3. **确定处理顺序**：球ID、碰撞对与同帧多组合成排序固定；不要让遍历或优化方式改变合成先后。
4. **版本记录**：rulesVersion包含参数、碰撞数据和计分规则；seed/sequenceVersion包含PRNG、权重和防重复策略。
5. **输入记录**：只记录被接受的投放 {tick,x}、复活/放弃等规则事件。x量化为固定坐标单位，校验冷却；记录结算tick以确认已终止。
6. **序列边界**：有限序列耗尽如何处理必须明确；不同平台跑同序列不等于所有物理结果自动一致。

每日日期由服务端按 Asia/Shanghai确定；离线挑战标成未验证。经典模式保留现有复活规则；每日模式可先沿用，但必须单独榜单、固定重试规则及版本。之后再试“少量固定复活”的策略版本，避免同时改太多变量。

当前 AVOID_REPEAT 使用最多6次拒绝采样后兜底，不能承诺永远不重复。先将它明确写进序列版本；如果改算法，发布新版本而不是静默影响历史回放。

### 5.2 验收与失败后的降级

- 同一版本、种子、输入日志在同一引擎反复运行，分数、合成顺序和终局一致。
- Chrome、Firefox、Safari做一批固定回放交叉验证；每局记录状态摘要与差异，而非仅比较最终分数。
- 校验30/60/120Hz显示刷新下同一输入日志的模拟结果；暂停、后台恢复不改变序列。
- 若跨平台浮点/数学函数差异导致长期分歧，先固定验证引擎并定位问题；可让服务端提供权威回放结果。必要时采用固定点/规定精度计算，这通常会延长工期，不默认承诺完成。
- 尚未稳定时只提供“同序列朋友挑战”和本地回放，公开榜继续标注未验证。

产品呈现：今日挑战、当天个人最佳、再挑战、复制挑战码/成绩卡。分享由玩家主动发起。一次只测试一种新模式；先观察重复挑战和重放失败，再增加限时或残局模式。

## 6. P1：按可测试的边界整理工程

预计6–10小时；逐块搬迁并验证行为，保留Canvas与原素材管线。

建议新增独立的 `game-src/`，因为当前 `src/` 已是原始图片目录：

```text
game-src/
  config.js          规则/资源/模式版本
  core/
    state.js         可序列化状态与迁移
    rng.js           游戏随机源
    physics.js       形状、碰撞、积分
    rules.js         合成、分数、复活、判负
    replay.js        tick推进与输入日志
  client/
    renderer.js      Canvas/粒子/插值
    input.js         鼠标触屏键盘→游戏命令
    audio.js         音效及设置
    ui.js            暂停、图鉴、结算
    storage.js       本地记录和存储容错
    leaderboard.js   网络契约与界面
tests/
tools/
docs/
```

核心层接收状态、输入和tick，不访问DOM、localStorage、Date或网络。渲染只读取模拟状态，粒子不改变模拟。客户端是适配层；未来服务端复用core完成验证。

运行时无需为了拆文件立刻迁移React或大型引擎。若继续双击index.html可运行，用普通script显式加载并导出受控命名空间；若改ES modules，则以HTTP启动并更新运行说明。打包可作为后续可选产物，不要让“零构建”与真实开发流程互相矛盾。

补规则状态图：playing → paused / revivePrompt → playing / settled；settled成绩只创建一次。调试句柄统一文档名称，生产入口可按配置隐藏，但它不是防作弊措施。

素材生成增加依赖版本记录、生成命令和结果清单；WebP、parts、blur由同一份资源定义生成。先测量再调整精度/子圆数量。

## 7. P1/P2：验证质量与性能，给作品集可复查的证据

### 7.1 测试分层（预计5–9小时）

保留现有VM测试作为快速回归，新增有实际失败价值的场景：
- 规则：跨多个2000分阈值、同帧多组合成、同帧清场与判负、旧局结算重复、复活后重新判负。
- 随机/回放：固定种子、输入日志黄金样例、拒绝非法输入、版本不匹配。
- 排行榜：模拟“写成功响应丢失”、超时、非JSON、429、离线、同分不同人、旧请求覆盖新局。
- 浏览器：真实CSS下hidden零占位、图鉴移动入口、pointercancel、多指、音频首次手势、旋转、弹窗焦点、存储异常。
- 压力：20/50/100个球、长局、弱网贴图、30Hz及高刷新显示、后台恢复；分清模拟测试与真实手机测试。

修正回弹指标：只计碰撞后超过可见速度阈值且达到最小离地高度的独立事件；第一次回弹高度仅在首个事件区间测量。保留微小残余速度指标作为另一项，而不是混为“弹跳次数”。

CI在提交和PR运行Node测试、语法/格式、HTTP浏览器冒烟；依赖锁版本并记录失败截图和回放。当前基线未跟踪CI配置或排行榜独立测试文件，历史提交说明提到的额外测试不能当成本次可执行证据。

### 7.2 先测量，再决定物理优化（预计3–6小时）

作者README中的物理耗时与IoU是作者报告，本次未重新测量。记录设备、系统、浏览器、球数、子圆数、输入序列、至少30秒预热后的一段采样。

建议目标（并非当前成绩）：指定中档手机在典型场景下帧耗时p95接近或低于16.7ms；低档设备先保30Hz、输入到反馈p95低于100ms。分别记录physics、render、总帧及内存，平均FPS不足以解释卡顿。

只有碰撞耗时成为瓶颈后再试空间网格/候选对缓存、世界坐标更新复用、稳定堆叠休眠。每项优化必须重新跑回放与碰撞边界，特别是大角色跨多网格、合成后唤醒和可重复处理顺序。表现降级优先减少粒子、阴影和像素倍率，避免设备不同导致不同规则。

### 7.3 作品集内容

新增技术说明、模块图、素材生成示例、问题修复前后对照、测试命令及实测表。说明PBD的游戏近似、旋转限制与自研原因，不包装成完整真实刚体引擎。展示一次真实故障如何靠回放定位，比只列技术名词更有说服力。

## 8. P2：长期体验、离线、数据与运营

- **个人成长**：本地记录最高等级、最佳分数、合成次数、挑战历史与个人进步；不同时加入一堆兑换货币。
- **分享**：结算页生成角色/分数/日期/规则版本卡；由用户主动保存或分享，不自动发消息。
- **离线**：目前本地文件可玩；添加到主屏幕的meta不等于完备PWA。需要manifest、图标、HTTPS和版本化Service Worker后才承诺离线安装体验。静态资源缓存，榜单请求不当离线成功处理；更新在局外生效，避免混用碰撞数据与旧规则。
- **续局**：先只支持经典本地模式。版本化快照包含球的位置/速度/角度、PRNG、tick、冷却、复活与计时；恢复后重建派生碰撞坐标并检查有限数值。公开挑战的跨刷新续局要有明确服务端契约，否则标成练习。
- **用户反馈**：先找10–20名玩家做小范围体验；记录新手理解、首局长度、误重开、复玩原因和卡顿设备。小样本只能辅助判断，不能证明广泛留存改善。
- **统计口径**：可选最小事件：game_start、first_drop、merge、game_over、challenge_retry、help_open、submit_error、frame_sample。游戏时长只算活跃时段，D1明确为当地下一日同一匿名玩家返回。昵称和完整回放不默认进入分析日志。
- **监控**：前端错误、API失败率、重放拒绝原因、验证队列长度与计算成本；保留关闭提交/退回本地榜的开关。
- **发布**：每版记录规则和资源版本，准备回滚。自己的Pages站点只能发布静态部分；可信榜单需要另行部署后端。清理配置归属后再发布你的游玩链接。
- **预算**：静态学习版不需要新增付费服务。后端先设置试运行月预算上限50–100元和计算配额，这是建议的预算控制值，非云厂商报价；选具体服务时重新核价。排行榜不可用应自然退回本地，不通过共享原账号绕过限制。

## 9. 实施排期与验收里程碑

下表是熟悉JavaScript的单人开发估算，前后存在依赖；初学者通常需要1.5–2倍时间。每日挑战的跨平台一致性若遇到难题应降级，不压缩验证。

| 阶段 | 交付 | 工时估算 | 放行条件 |
|---|---|---:|---|
| 第1周 | 玩法图鉴、暂停/存储/输入保护、实例配置 | 9–16h | 手机可理解、存储异常可玩、独立开发不写原榜 |
| 第2周 | 模块拆分、可读排行榜、本地榜及核心回归 | 10–17h | 现有测试继续通过，逻辑可脱离DOM运行 |
| 第3周 | 游戏PRNG、tick、固定序列、输入回放 | 8–14h | 固定版本固定日志可复现，平台差异已记录 |
| 第4周 | API/数据库、幂等、服务端验证、榜单 | 12–20h | 服务端算分，非法/重复/旧版本成绩被正确处理 |
| 第5周 | 浏览器/压力测试、性能基线、反馈 | 8–15h | 实机问题可重现并修复，预算与故障降级有效 |
| 第6周（可选） | PWA/续局/分享/作品集完善 | 8–14h | 更新不污染旧局，续局有版本校验 |

主线约47–82小时，选做约8–14小时；这是范围估计，未包括素材重绘、账号体系、大幅物理算法重写。

预算/时间紧时，完成第1–3周就能形成明显升级的静态作品；远程榜保留“未验证”标签即可。有公开竞赛目标再完成第4–5周，不让进阶工作依赖一开始就购买云服务。
